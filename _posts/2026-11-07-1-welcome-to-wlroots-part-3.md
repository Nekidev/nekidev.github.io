## Initializing XDG

We currently have barely any globals set up. XDG requires one, so let's create it. The types for
our global will mostly live under `wlr/types/wlr_xdg_shell.h`.

```c
#include <wlr/types/wlr_xdg_shell.h>
```

You may already know that Wayland protocols are described via XML and that we have to autogenerate
code to use those protocols. If you didn't know that, all good. It's just adding some commands to
our Makefile.

```makefile
# The directory where our protocols are defined.
PROTOCOLS_XML=$(shell pkg-config --variable=pkgdatadir wayland-protocols)
# The path to the XDG shell protocol definition.
XDG_SHELL_XML=$(PROTOCOLS_XML)/stable/xdg-shell/xdg-shell.xml
```

We'll be storing our autogenerated code in a new folder called `wayland/` under our project. Make
sure to have `libwayland-dev` and `wayland-protocols` installed on your system.

Our build command will then look like this:

```makefile
build:
	mkdir -p wayland
	wayland-scanner server-header "$(XDG_SHELL_XML)" wayland/xdg-shell-protocol.h
	wayland-scanner private-code "$(XDG_SHELL_XML)" wayland/xdg-shell-protocol.c
	# markdown formater is not letting me keep this line empty, remove this comment
	mkdir -p build
	clang src/main.c $(FLAGS)
```

Now yes! Time to create our XDG shell global.

```c

    // -- snip --
};

int main(void) {
    // -- snip --
```

A note on the version, we're using number 6 even when the latest version is number 7 because
`wlroots-0.19` does not come with support for number 7. At the time of writing, `wlroots-0.20` is
already available with support for the latest version. I have not checked it out, it may work out
of the box but you may have to do some investigation on your own to see if anything has changed in
the code we're using here.

## More Globals

We'll start by handling top-level windows. They're called top-levels because they're the highest in
the window hierarchy. Popups and dropdown menus will always be children of a top-level.

Top-levels and popups are just wrappers over a surface. They get extra methods to call and events
to receive based on the role (top-level and popups are "roles") the surface has. E.g. you can
request to full-screen a top-level, but not a popup.

Same as we did with our outputs, we'll listen for new window events and add them to our scene.

```c
struct nye_server {
    // -- snip --
    struct wl_listener on_xdg_toplevel_add;
    // -- snip --
};

static void on_xdg_toplevel_add(struct wl_listener*, void*) {
    printf("New toplevel!\n");
}

int main(void) {
    // -- snip --
    nye_server.wlr_xdg_shell = wlr_xdg_shell_create(nye_server.wl_display, 6);
    assert(nye_server.wlr_xdg_shell);

    nye_server.on_xdg_toplevel_add.notify = on_xdg_toplevel_add;
    wl_signal_add(&nye_server.wlr_xdg_shell->events.new_toplevel, &nye_server.on_xdg_toplevel_add);
    // -- snip --
}
```

To test things out, I'll be using `weston-simple-shm` from the `weston` compositor package. Weston
is Wayland's official reference compositor, so the package comes with the compositor too. We only
want it for the dev tooling.

```
$ WAYLAND_DISPLAY=way-nyeki weston-simple-shm

```

Wayland clients send the compositor their window graphics by **SH**aring **M**emory. This makes the
transport way more efficient than by making a copy of all pixel data and sending it over the socket
connection directly. There are also other globals that do similar things, like Linux's dmabuf (for
rendering on the GPU instead of on the CPU).

Fortunately, initializing `wl_shm` is as simple as calling a function on our display. Let's do
that.

```c
// -- snip --
#include <wlr/types/wlr_shm.h>

int main(void) {
    // -- snip ---
    wlr_shm_create_with_renderer(nye_server.wl_display, 2, nye_server.wlr_renderer);
    // -- snip --
}
```

Again, the `wl_shm` global's latest version at the time of writing is number 3. However, we're
using `wlroots-0.19` which does not have support for that version, so we use number 2 instead.

## Listening for New Windows

Great! Now we're getting new windows to fire the callback in our compositor, so we can now do stuff
about it.

The first thing we want to do is to create YAW (yet another wrapper) for toplevels.

```c
struct nye_server {
    // -- snip --
    struct wl_list nye_xdg_toplevels; // nye_xdg_toplevel::link
    // -- snip --
};

struct nye_xdg_toplevel {
    struct wl_list link; // nye_server::nye_xdg_toplevels

    struct nye_server *nye_server;
    struct wlr_xdg_toplevel *wlr_xdg_toplevel;

    struct wl_listener on_xdg_toplevel_del;
};

static void on_xdg_toplevel_del(struct wl_listener*, void*) {
    printf("Bye toplevel!\n");
}

static void on_xdg_toplevel_add(struct wl_listener*, void*) {
    printf("New toplevel!\n");
}

int main(void) {
    // -- snip --
    wl_list_init(&nye_server.nye_xdg_toplevels);
    nye_server.on_xdg_toplevel_add.notify = on_xdg_toplevel_add;
    // -- snip --
}
```

Next, we'll have to create and store our new wrappers in the `nye_xdg_toplevel` wrapper.

XDG surfaces have a little handshake before they can be rendered on the screen. They use this to
send the compositor their initial properties, such as app name and window title, and to send their
*ideal* properties, such as size. Size is ideal because the app may want to have a specific size,
but it's ultimately on the compositor to decide what size it actually gets. When the compositor is
done setting all those properties, it sends a `configure` event, the client acknowledges it, and
the rendering starts.

XDG surfaces work by sending over pending changes to the compositor and then committing them with a
`commit()` call. The flow is more or less like this:

1. The client creates a surface
2. The client creates a top-level to wrap it
3. The client sets its inital data (e.g. window title, app name)
4. The client commits all the initial data with a `commit()`
5. The compositor stores that data and sends the client a `configure` event with its resulting
   initial state
6. The client acknowledges that configuration
7. The client starts rendering

First, let's handle adding and removing the XDG toplevels from our server's list to be done with
the boilerplate.

```c
static void on_xdg_toplevel_del(struct wl_listener *wl_listener, void *)
{
    printf("Bye toplevel!\n");

    struct nye_xdg_toplevel *nye_xdg_toplevel = wl_container_of(wl_listener, nye_xdg_toplevel, on_xdg_toplevel_del);

    wl_list_remove(&nye_xdg_toplevel->link);
    wl_list_remove(&nye_xdg_toplevel->on_xdg_toplevel_del.link);

    free(nye_xdg_toplevel);
}

static void on_xdg_toplevel_add(struct wl_listener *wl_listener, void *data)
{
    printf("New toplevel!\n");

    struct nye_server *nye_server = wl_container_of(wl_listener, nye_server, on_xdg_toplevel_add);
    struct wlr_xdg_toplevel *wlr_xdg_toplevel = data;

    struct nye_xdg_toplevel *nye_xdg_toplevel = calloc(1, sizeof(struct nye_xdg_toplevel));
    nye_xdg_toplevel->nye_server = nye_server;
    nye_xdg_toplevel->wlr_xdg_toplevel = wlr_xdg_toplevel;

    nye_xdg_toplevel->on_xdg_toplevel_del.notify = on_xdg_toplevel_del;
    wl_signal_add(&wlr_xdg_toplevel->events.destroy, &nye_xdg_toplevel->on_xdg_toplevel_del);

    wl_list_insert(&nye_server->nye_xdg_toplevels, &nye_xdg_toplevel->link);
}
```

Boilerplate done, time to get to the fun part.

`wlr_output` has a `wlr_scene_output`, but our `wlr_xdg_toplevel` will get a `wlr_scene_tree`. This
is because, as we explained before, `xdg_toplevel` is the parent of its popups and other surfaces
that will get rendered with it.

Our toplevel is just a surface underneath, so let's add that surface to the scene.

```c
struct nye_xdg_toplevel
{
    // -- snip --
    struct wlr_scene_tree *wlr_scene_tree;
    // -- snip --
};

static void on_xdg_toplevel_add(struct wl_listener *wl_listener, void *data)
{
    // -- snip --
    nye_xdg_toplevel->wlr_xdg_toplevel = wlr_xdg_toplevel;

    nye_xdg_toplevel->wlr_scene_tree = wlr_scene_xdg_surface_create(&nye_server->wlr_scene->tree, wlr_xdg_toplevel->base);
    // -- snip --
}
```

`wlr_xdg_toplevel::base` is the XDG surface the top-level wraps, which is itself a wrapper over a
`wl_surface`.

## 🤝

`wlr_scene` won't send the initial configuration to the client, so it won't render anything until
we handle the handshake ourselves. This part is easy, we'll just tell the client to choose its own
size.

Configuration events get fired after the client sends its first commit, so let's wait for it first.

```c
struct nye_xdg_toplevel
{
    // -- snip --
    struct wl_listener on_xdg_surface_commit;
};

static void on_xdg_surface_commit(struct wl_listener *, void *) {}

static void on_xdg_toplevel_del(struct wl_listener *wl_listener, void *)
{
    // -- snip --
    wl_list_remove(&nye_xdg_toplevel->on_xdg_toplevel_del.link);

    wl_list_remove(&nye_xdg_toplevel->on_xdg_surface_commit.link);

    free(nye_xdg_toplevel);
}

static void on_xdg_toplevel_add(struct wl_listener *wl_listener, void *data)
{
    // -- snip --
    
    nye_xdg_toplevel->on_xdg_surface_commit.notify = on_xdg_surface_commit;
    wl_signal_add(&wlr_xdg_toplevel->base->surface->events.commit, &nye_xdg_toplevel->on_xdg_surface_commit);

    wl_list_insert(&nye_server->nye_xdg_toplevels, &nye_xdg_toplevel->link);
}
```

Great! Now that that's done, let's just check if the commit we received is the first commit. If it
is, we set its size to 0x0 (which means to let the client pick its own size).

```c
static void on_xdg_surface_commit(struct wl_listener *wl_listener, void *) {
    struct nye_xdg_toplevel *nye_xdg_toplevel = wl_container_of(wl_listener, nye_xdg_toplevel, on_xdg_surface_commit);

    // Our wrapper -> XDG top-level -> XDG surface -> Is this the first commit?
    if (nye_xdg_toplevel->wlr_xdg_toplevel->base->initial_commit) {
        // Calling wlr_xdg_toplevel_set_* schedules a configure event. It'll be sent when this
        // callback is done running. Calling multiple set_* will batch them into a single configure
        // event.
        wlr_xdg_toplevel_set_size(nye_xdg_toplevel->wlr_xdg_toplevel, 0, 0);
    }
}
```
